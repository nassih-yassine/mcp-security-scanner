# Releasing

One version for both crates. Tags are `vX.Y.Z` and must equal
`[workspace.package] version` in `Cargo.toml`; the publish job rejects a mismatch.

## Before the tag

1. `cargo xtask gen-docs` and commit any change (CI runs `--check`).
2. Update `CHANGELOG.md` (`git cliff --unreleased --prepend CHANGELOG.md`).
3. Bump `[workspace.package] version` in `Cargo.toml`. The `mcpscan` dependency on
   `mcpscan-core` is version-locked (`=X.Y.Z`); update it in the same commit.
4. `cargo test --locked`, `cargo clippy --locked --all-targets -- -D warnings`,
   `cargo fmt --check`, `cargo deny check`.
5. `dist plan` — confirm the five targets and that nothing unexpected ships.
6. Confirm the README sample output still matches `mcpscan scan fixtures/demo`.

## The tag

```bash
git tag vX.Y.Z
git push origin vX.Y.Z
gh run watch
```

`release.yml` (generated by cargo-dist, hand-edited for permissions) builds and
attests the artifacts. A token-created release never starts other workflows, so
`cargo-publish.yml` acts on `workflow_run` of `Release`.

## After the tag

1. Approve the `crates-io` environment deployment.
2. Smoke test from a clean container:
   `cargo binstall mcpscan --version`, and run the action against a scratch repo.
3. Update the GitHub About description if the one-liner changed.
4. Publish the release notes from `CHANGELOG.md`.

## Versioning rules

- Pre-1.0: breaking changes may land in a minor, always in the CHANGELOG.
- Rule IDs are frozen once released. Renaming or removing one ships a mapping
  table in the CHANGELOG.
- A severity change on an existing rule is a minor (dismissals and baselines
  key on it).
- New rule: minor. Docs or metadata only: patch.

## Prereleases

`vX.Y.Z-alpha.N` builds artifacts but does not publish to crates.io; the tag
validator only accepts stable `vX.Y.Z` for publishing.

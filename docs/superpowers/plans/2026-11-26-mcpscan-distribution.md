# mcpscan Distribution Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `mcpscan` through every channel in `SPEC.md` §4.11 — GitHub Release binaries, crates.io, npm (`npx`), a composite GitHub Action, and Linux packages — with the docs that keep them honest.

**Architecture:** `cargo-dist` generates the release workflow and installers from `dist-workspace.toml`. Each channel keeps its own workflow, triggered by `workflow_run` of `Release` (a `GITHUB_TOKEN`-created release never starts workflows), and each declares an environment with required reviewers. The Action is a composite that downloads the pinned release binary — no third-party actions in a supply-chain tool.

**Tech Stack:** `cargo-dist` 0.34, `git-cliff`, `nfpm`, `gh release upload`, GitHub Environments.

**Spec:** `SPEC.md` §4.11, §4.12. **Depends on:** `docs/superpowers/plans/2026-11-26-mcpscan-mvp.md` (all tasks complete, `v0.1.0-alpha.1` taggable).

## Global Constraints

Same as the MVP plan: exit codes `0/2/3`, no raw secrets, offline by default, generated docs never hand-edited. Plus:

- Every publishing job declares an environment (`release`, `crates-io`, `npm-publish`, `linux-packages`).
- Release workflows act on `workflow_run` of `Release`, reading the tag from `workflow_run.head_branch`.
- Third-party actions pinned to a commit SHA with a `# vX` comment; Dependabot ignores generated `release.yml`.
- Tag must match `[workspace.package] version` or the publish job fails.
- Never hand-build and upload a release artifact; `cargo dist` produces all of them.

## Review Focus

1. **A tag that does not match `Cargo.toml`** — publish jobs must fail loudly, not ship `0.1.0` from a `v0.2.0` tag. (Task 2)
2. **`npx mcpscan` on a machine without a prebuilt target** — must fall back to building, not exit silently. (Task 3)
3. **A workflow that runs on the wrong event** — `release: created` never fires for token-created releases; the channel silently never publishes. (Task 1)
4. **An Action that pins a floating ref** — `uses: mcpscan@v1` must resolve the binary from the action's own tag, not `main`. (Task 4)
5. **Package install scripts** — a `.deb` for a security tool must contain no maintainer scripts. (Task 5)

### Task 1: cargo-dist release workflow

**Files:**
- Create: `dist-workspace.toml`
- Modify: `Cargo.toml` (`[workspace.metadata.dist]` not needed; keep dist config in its own file)

**Interfaces:**
- Produces: `release.yml` generated by `cargo dist generate`, building 7 targets with shell+powershell installers and SLSA attestations.

- [ ] **Step 1: Write `dist-workspace.toml`**

```toml
[workspace]
members = ["cargo:."]

[dist]
cargo-dist-version = "0.34.0"
allow-dirty = ["ci"]
ci = "github"
installers = ["shell", "powershell"]
targets = [
  "aarch64-apple-darwin",
  "aarch64-unknown-linux-musl",
  "x86_64-apple-darwin",
  "x86_64-unknown-linux-musl",
  "x86_64-pc-windows-msvc",
]
github-attestations = true
```

`allow-dirty = ["ci"]` is mandatory: `release.yml` is generated, then hand-edited for least-privilege permissions. Regenerate only when upgrading dist, and reapply those edits.

- [ ] **Step 2: Generate and dry-run**

Run: `cargo dist plan`
Expected: lists the five targets, no errors. If `cargo-dist` is missing: `cargo install cargo-dist --locked`.

Run: `cargo dist generate --check`
Expected: exits non-zero before generation, zero after `cargo dist generate`.

- [ ] **Step 3: Pin the generated workflow's actions**

Add the commit pins under `[dist.github-action-commits]` for `actions/checkout`, `actions/upload-artifact`, `actions/download-artifact`, `actions/attest`, regenerate, and confirm `grep -c 'uses: [^ ]*@[0-9a-f]\{40\}' .github/workflows/release.yml` equals the number of `uses:` lines.

- [ ] **Step 4: Verify the event wiring**

Assert `release.yml` triggers on `push: tags: ["v*"]` (not on `release:`), and that no job requires a secret at build time.

### Task 2: crates.io publish

**Files:**
- Create: `.github/workflows/cargo-publish.yml`

**Interfaces:**
- Produces: a job that publishes `mcpscan-core` then `mcpscan` on a successful `Release` run, gated by the `crates-io` environment.

- [ ] **Step 1: Write the workflow**

```yaml
name: cargo publish
on:
  workflow_run:
    workflows: ["Release"]
    types: [completed]
  workflow_dispatch:
    inputs:
      tag: { description: "Release tag (vX.Y.Z)", required: true }
permissions:
  contents: read
jobs:
  publish:
    if: github.event_name == 'workflow_dispatch' || github.event.workflow_run.conclusion == 'success'
    runs-on: ubuntu-latest
    environment: crates-io
    env:
      TAG: ${{ github.event_name == 'workflow_run' && github.event.workflow_run.head_branch || inputs.tag }}
    steps:
      - uses: actions/checkout@<sha> # v6
        with: { ref: "${{ env.TAG }}", persist-credentials: false }
      - name: Validate tag against Cargo.toml
        run: |
          printf '%s' "$TAG" | grep -Eq '^v[0-9]+\.[0-9]+\.[0-9]+(-[0-9A-Za-z.]+)?$' || { echo "::error::bad tag $TAG"; exit 1; }
          v="${TAG#v}"
          w="$(sed -n 's/^version = "\(.*\)"$/\1/p' Cargo.toml | head -1)"
          [ "$v" = "$w" ] || { echo "::error::tag $TAG != Cargo.toml $w"; exit 1; }
      - run: cargo publish -p mcpscan-core --locked
        env: { CARGO_REGISTRY_TOKEN: "${{ secrets.CARGO_REGISTRY_TOKEN }}" }
      - run: sleep 30 && cargo publish -p mcpscan --locked
        env: { CARGO_REGISTRY_TOKEN: "${{ secrets.CARGO_REGISTRY_TOKEN }}" }
```

The `sleep 30` is not decorative: crates.io index propagation is eventually consistent and `mcpscan` depends on `mcpscan-core = "=<version>"`. Use the version-locked dependency form so a stale index cannot resolve an older core.

- [ ] **Step 2: Verify locally without publishing**

Run: `cargo package -p mcpscan-core --locked --list && cargo package -p mcpscan --locked --list`
Expected: both list files, no paths outside the crate, `mcpscan` includes `src/main.rs`.

- [ ] **Step 3: Verify the tag guard**

Run: `bash -c 'TAG=v0.9.9; sed -n "s/^version = \"\(.*\)\"$/\1/p" Cargo.toml | head -1'`
Expected: prints `0.1.0`, so the guard in step 1 would reject `v0.9.9`.

- [ ] **Step 4: Create the environment**

```bash
gh api -X PUT repos/nassih-yassine/mcp-security-scanner/environments/crates-io \
  --input - <<'JSON'
{"deployment_branch_policy": {"protected_branches": true, "custom_branch_policies": false}}
JSON
```

Add required reviewers in repo settings → Environments → `crates-io`.

- [ ] **Step 5: Commit**

```bash
git add .github/workflows/cargo-publish.yml
git commit -m "ci: publish to crates.io behind an environment"
```

### Task 3: npm package (`npx mcpscan`)

**Files:**
- Create: `.github/workflows/npm-publish.yml`, `npm/package.json`

**Interfaces:**
- Produces: an npm package whose postinstall downloads the matching release binary per platform, falling back to `cargo install`.

- [ ] **Step 1: Write `npm/package.json`**

Fields: `name: "mcpscan"`, `bin: { "mcpscan": "./run.js" }`, `optionalDependencies` for the per-platform packages if you ship them, `engines.node >= 18`, `license: MIT`, `repository`.

`run.js` resolves `require.resolve("mcpscan-<platform>-<arch>/bin/mcpscan")`, and if missing, spawns `cargo install mcpscan --locked` once with a clear stderr message. It must never silently exit 0.

- [ ] **Step 2: Test the resolution logic without publishing**

Run: `node npm/run.js --version`
Expected: prints the version if a local binary is on PATH, otherwise the `cargo install` fallback message and a non-zero exit — never a silent success.

- [ ] **Step 3: Write the publish workflow**

Same `workflow_run` + `environment: npm-publish` shape as Task 2, tag validated the same way, `npm publish --provenance --access public` with `NODE_AUTH_TOKEN`.

- [ ] **Step 4: Verify the guard**

Run: `node -e 'const p=require("./npm/package.json"); if(p.name!=="mcpscan") process.exit(1)'`
Expected: exit 0. And confirm on npmjs.com that `mcpscan` is unclaimed before the first publish; if taken, rename here and in `SPEC.md` §9 Q5.

- [ ] **Step 5: Commit**

```bash
git add npm .github/workflows/npm-publish.yml
git commit -m "ci: ship mcpscan on npm"
```

### Task 4: GitHub Action

**Files:**
- Create: `action.yml`

**Interfaces:**
- Produces: a composite action with inputs `path` (default `.`), `format` (default `sarif`), `output` (default `mcpscan.sarif`), `fail-on` (default `critical`), `version` (default: the action's own tag), `upload` (default `true`).

- [ ] **Step 1: Write `action.yml`**

Composite steps: resolve the version from `github.action_ref` when `version` is empty; download `mcpscan-<target>.tar.gz` from the release using `curl` with `--fail --location --proto '=https'`; verify against `sha256.sum`; extract to `$RUNNER_TEMP/mcpscan`; add to `PATH`; run `mcpscan scan "$INPUT_PATH" --format "$INPUT_FORMAT" --output "$INPUT_OUTPUT" --fail-on "$INPUT_FAIL_ON"`; when `upload` is `true`, run `github/codeql-action/upload-sarif@<sha>` (the only third-party action allowed, and only because SARIF upload has no first-party alternative).

- [ ] **Step 2: Test locally with a development binary**

```bash
MCPScan_LOCAL_BIN="$(cargo build -q && pwd)/target/debug/mcpscan" \
  bash -c 'export INPUT_PATH=fixtures/demo INPUT_FORMAT=human INPUT_OUTPUT="" INPUT_FAIL_ON=high; '
```
Add a branch at the top of the script step: if `MCPScan_LOCAL_BIN` is set, skip download and use it. That branch exists only for local verification and CI smoke tests, never as documented user input.

- [ ] **Step 3: Verify shell safety**

Run: `bash -n` on each extracted `run:` block, and confirm every input reaches the script through a quoted `env:` value — never interpolated into shell text (command injection via `path`).

- [ ] **Step 4: Verify with `actionlint`**

Run: `actionlint action.yml`
Expected: no findings. If `actionlint` flags the download step, fix the quoting rather than ignoring the rule.

- [ ] **Step 5: Commit**

```bash
git add action.yml
git commit -m "feat: composite github action with sarif upload"
```

### Task 5: Linux packages and brew

**Files:**
- Create: `.github/workflows/packaging.yml`, `packaging/nfpm.yaml`
- Create: `docs/RELEASING.md`, `cliff.toml`, `.github/workflows/commit-lint.yml`

- [ ] **Step 1: Write `packaging/nfpm.yaml`**

`deb`, `rpm`, `apk`, `archlinux` sections; `version` from `$MCPScan_VERSION`, `arch` from `$MCPScan_ARCH`; files: `mcpscan` → `/usr/bin/mcpscan`, `README.md` → `/usr/share/doc/mcpscan/README.md`, `LICENSE`; **no `scripts:` key** — a security tool's package must not run code of its own at install time.

- [ ] **Step 2: Write the workflow**

`workflow_run` of `Release`, stable `vX.Y.Z` only (prereleases skipped), downloads the attested musl archives, verifies `sha256.sum`, runs a checksum-pinned `nfpm`, then `gh release upload --clobber`. Environment: `linux-packages`.

- [ ] **Step 3: Verify the package contains no install scripts**

```bash
dpkg-deb -c mcpscan_*.deb | grep -E 'control|postinst|preinst' || true
dpkg-deb -I mcpscan_*.deb | grep -i 'script' && echo "FAIL: has scripts" || echo "OK: no maintainer scripts"
```
Expected: `OK: no maintainer scripts`.

- [ ] **Step 4: Write the release checklist and changelog config**

`docs/RELEASING.md`: regenerate docs (`cargo xtask gen-docs --check`), CHANGELOG entry, bump `[workspace.package] version`, `cargo dist plan`, tag `vX.Y.Z`, wait for `Release`, approve `crates-io` and `npm-publish` environments, smoke test `cargo binstall mcpscan --version` and `npx mcpscan --version` in a clean container, update the About description and README badge.

`cliff.toml`: conventional-commit groups (feat → "Added", fix → "Fixed", perf → "Performance", docs → skip, chore/ci → skip). `commit-lint.yml`: PR title and commit subject must match `^(feat|fix|perf|docs|refactor|test|chore|ci)(\(.+\))?!?: .+`.

- [ ] **Step 5: Verify the checklist end to end on a prerelease**

Run: `git tag v0.1.0-alpha.1 && git push origin v0.1.0-alpha.1 && gh run watch`
Expected: `Release` succeeds with five artifacts and attestations; `cargo-publish` and `npm-publish` are skipped for a prerelease if you gate them on `v[0-9]+\.[0-9]+\.[0-9]+$` — decide explicitly and record the choice in `docs/RELEASING.md`.
